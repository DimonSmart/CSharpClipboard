# IDD-0012.spike-macos-dotnet-bridge-and-permissions

## Question

может ли `.NET 10 + Avalonia .app`, запущенная из Finder, через Swift/ObjC bridge корректно читать `NSPasteboard.accessBehavior`, считать `changeCount` без prompts, user-initiated request once, получать AX permission, захватывать исходный focused element и регистрировать `SMAppService.mainApp`?

## Constraints

Контракты IDD-0001, IDD-0002, IDD-0004, IDD-0005, IDD-0009, IDD-0010 обязательны. Реальные macOS/Windows проверки не заменяются фейками; не логировать содержимое.

## Method

**Минимальный прототип:** статус-элемент + кнопка Permission state + Request Once + один tick/read + AX snapshot + лог только состояний + сборка signing + запуск из Finder. Отдельно сравнить с `dotnet run`.

**Матрица:** clean `.default`, `.ask`, `.alwaysAllow`, `.alwaysDeny`, accessibility granted/denied, dev/release signing distinction, permission changes during runtime, reopen app, macOS arm64 real host.

**Успех:** все expected transitions воспроизведены; no permission loops; bridge работает из `.app` без missing dylibs; сохраняется корректная thread ownership. Если bridge не выдерживает requirements — ADR с альтернативой до полного UI.

## Result

Вопрос открыт. Проверки нового приложения не выполнены. Evidence ClipboardMac не подтверждает CSharpClipboard.

## Recommendation

Проверить минимальный прототип до полноценного UI. Подтверждённое поведение перенести в спецификации, выбранные устойчивые решения — в ADR/Engineering; недоказанные возможности явно not verified.
