# IDD-0002.spec-clipboard-capture-and-privacy

## Intent

Сохранять точный допустимый plain text с соблюдением приватности и согласованности ревизий.

## Behavior

### Семантика «перехвата»
- «Перехват» означает **наблюдение за системным clipboard после изменения**, а не блокирование операции Copy, не низкоуровневый keylogger, не hook каждого Ctrl/Cmd+C.
- macOS: опрос `NSPasteboard.general.changeCount` каждые **500 мс**, в подходящем main run loop; API не гарантирует обнаружения каждого промежуточного копирования.
- Windows: `AddClipboardFormatListener` + `WM_CLIPBOARDUPDATE` с живым message loop/окном-получателем, а для согласованности — `GetClipboardSequenceNumber`. Избегать 500-ms polling как основного механизма Windows.
- Обработчики сериализованы: никакие два параллельных capture read + DB write не пересекаются; callbacks никогда не блокируют UI длительной работой с SQLite.
- Ревизия clipboard фиксируется **до** чтения и перепроверяется **после**: если данные менялись во время чтения, полученная смесь/устаревшая ревизия не сохраняется; новое изменение будет обработано следующим событием/тиком.
- Ошибка чтения или временная блокировка Windows clipboard не приводит к сохранению неверного значения. Предусмотреть bounded retry/backoff только пока наблюдаемая ревизия всё ещё актуальна; не создавать бесконечные retry/permission prompts.

### Допустимые данные
- Захватывается **ровно один** clipboard item, содержащий plain-text представление. Допустимо получить plain text как представление rich copy, если оно действительно присутствует.
- Игнорировать clipboard без plain text; файлы (в т. ч. file URL), изображения, наборы нескольких элементов и составные опасные варианты.
- Принимать текст без преобразований: сохранять точные Unicode code points, пробелы, табуляции, CRLF/LF, нулевые символы, регистр, завершающие пробелы/переносы. Никаких `Trim`, Unicode normalization или конвертации конца строки.
- Пустую строку игнорировать; строка только из whitespace — допустима.
- Максимум — **1 048 576 байт в UTF-8**. Граница включительно; больший текст пропускать без зависания UI.
- Если clipboard data помечены защищёнными, временными или автогенерированными, запись **полностью** пропускается, даже при наличии plain text.
- База хранит plaintext. Это должно быть сообщено пользователю; обещания защиты от администратора/вредоносных программ не давать.

### Источники и исключения
- Пользователь задаёт список идентификаторов приложений, для которых **новые** копирования игнорируются; уже сохранённое не удаляется. Исключение не мешает вставке в это приложение.
- macOS: использовать exact bundle ID (`com.apple.Safari`), значение от `org.nspasteboard.source` только после валидации, затем best-effort last external foreground app; не выдавать fallback за доказанную атрибуцию.
- Windows: использовать документированный стабильный идентификатор процесса/приложения; отдельно определить нормализацию и сохранение (напр. имя executable + проверяемая идентичность) в Windows-адаптере; не применять формально macOS bundle ID к `.exe`.
- Clipboard API **не гарантируют достоверное приложение-источник**. Если источник неизвестен, записать с `source = null` допустимо (как в референсе), UI явно объясняет, что exclusions являются best-effort, а не защитой от всех секретов. Не придумывать источник.
- На macOS пропускать `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType` и fileURL; при необходимости добавлять проверенные, задокументированные дополнительные markers password managers. Не создавать собственный ложный критерий «это секрет».
- Windows: принимать во внимание зарегистрированные форматы `ExcludeClipboardContentFromMonitorProcessing` и `CanIncludeInClipboardHistory=0`, если установлены; `CanUploadToCloudClipboard=0` само по себе относится к системной синхронизации, а не обязательно запрещает локальную историю, поэтому **не считать его автоматически маркером исключения** без отдельной задокументированной политики. Обработка Windows markers и форматов проверяется тестами.

### Собственные записи в буфер
- При выборе Copy Only/Paste приложение записывает точный текст в системный clipboard.
- Собственный clipboard write не создаёт новую запись истории, однако **следующее внешнее копирование не должно быть потеряно**, включая гонку непосредственно после собственной записи.
- Использовать реальную итоговую ревизию собственной операции и платформенные generated markers, где поддерживаются; нельзя просто «игнорировать следующий callback» или «подавлять всё на 500 мс».
- macOS: добавить `org.nspasteboard.AutoGeneratedType` к собственной записи; из-за требований безопасности достаточно пробовать подавление и маркером, и строгим учётом ревизии. Windows: собственное изменение распознаётся через sequence number после коммита; при наличии поддерживаемого private registered format допустим дополнительный marker без нарушения совместимости вставки.
- Содержимое системного буфера **остаётся выбранным текстом** после Paste/Copy Only; прежнее содержимое автоматически не восстанавливается.

### macOS — самостоятельное принципиальное требование
- **Запрещено** читать general pasteboard программно в фоне, пока пользователь не разрешил для приложения режим `Always Allow`. Это касается не только `.string`, но и API содержимого (`types`, `pasteboardItems`, чтение маркеров), которые могут инициировать privacy prompt.
- Проверять `NSPasteboard.general.accessBehavior` отдельно от accessibility. Состояния: `.default`, `.ask`, `.alwaysAllow`, `.alwaysDeny`.
- `.default`: приложение ещё не вызывало системный alert и может **не отображаться** в списке clipboard privacy в System Settings. При `.ask` следующий программный read может вызвать запрос. В обоих состояниях **автоматический опрос содержимого запрещён**.
- Если разрешение отсутствует, показывать `Clipboard Access Required` и инструкцию. Кнопка `Request Clipboard Access Once` может **по явному клику** совершить пользовательски инициированную попытку чтения для появления системного запроса. Не использовать эту кнопку как «установить Always Allow» и не обещать, что один ответ системе даст permanent allow.
- При `.alwaysDeny` не пытаться автоматически повторно запрашивать разрешение; предложить открыть настройки приватности macOS. При изменении политики в System Settings периодически перечитывать **статус**, но не содержимое, и активировать capture, только когда `.alwaysAllow`.
- При запрете доступа сохранённая история, поиск, pin/delete и Copy Only должны продолжать работать.
- Без Accessibility разрешения захват текста **может** работать при Always Allow. Нельзя связывать оба разрешения одним флагом.

## Product-Significant Architecture And Constraints

Поддерживаемые платформы и общие ограничения определяет IDD-0001. Наблюдаемые гарантии этого документа обязательны независимо от внутренней реализации.

## Non-goals

Нет гарантии обнаружить каждую копию или достоверно определить источник; exclusions не гарантируют защиту от всех секретов.

## Acceptance Criteria

- Повторное считывание без изменения ревизии не добавляет дубль.
- Unicode, пробелы и line endings идентичны исходному UTF-8.
- Запись, превышающая лимит, защищённые маркеры и file URL не сохраняются.
- Pause, `.default`, `.ask`, `.alwaysDeny` на macOS **не вызывают чтение содержимого** и не вызывают prompt loops.
- После собственного write быстрое внешнее copy сохраняется корректно, чужой текст не теряется.
- На Windows clipboard update обнаруживается без глобального keyboard hook; временное `OpenClipboard` contention не портит историю.
- Пользователь понимает ограничения «не все clipboard changes обнаруживаются» и «источники определяются best-effort».

## Verification

Проверить границы UTF-8, markers, sources, exclusions, стабильность ревизии и гонки собственных/внешних записей. Реальные clean macOS четыре AccessBehavior, отсутствие фоновых prompts и Windows contention. Диагностика не содержит текста.
