# IDD-0009.spec-macos-system-integration

## Behavior

### Scope
Требования **только macOS**. Их нельзя «спрятать» за абстрактным cross-platform clipboard implementation, если результат теряет свойства оригинала.

### 1. Identity, `.app` и TCC
- Приложение распространяется в `.app` bundle с **постоянным новым** `CFBundleIdentifier` для CSharpClipboard (не копировать ID `local.clipboardmac.ClipboardMac`, иначе возможно нежелательное смешение identity/privacy со старым приложением).
- Требуемые metadata: `CFBundleExecutable`, `CFBundleName`, `CFBundleDisplayName`, `CFBundleShortVersionString`, `CFBundleVersion`, `LSMinimumSystemVersion=26.0`, `LSUIElement=true`, app icon, executable permissions.
- `LSUIElement` обеспечивает menu-bar-agent без Dock; приложение всё равно должно правильно активировать History/Settings и получать фокус клавиатуры.
- **TCC/privacy-доверие связано не только с названием процесса.** Различать `dotnet run`, запуск из Rider/Terminal, unsigned build, ad-hoc signed .app, release подписанный Developer ID; Apple применяет code signing designated requirement для идентификации приложения.
- Нельзя обещать, что разрешения, выданные старому ClipboardMac или dev host, автоматически перейдут в новое `.app`. Нужны инструкции повторного предоставления доступа и постоянная identity/signing в рамках нового приложения.
- В debug/test обязательно запускать из *реального .app* с фиксированным bundle ID/signing; работа лишь из Terminal **не** подтверждает поведение разрешений Finder-launched app.
- App Store sandboxed distribution не входит в MVP.

### 2. Clipboard Access Privacy (обязательно)
- Реализация через AppKit NSPasteboard API, доступная из .NET через корректный native bridge; не подменять чтением Cocoa Clipboard объекта из Avalonia без проверки новой macOS privacy policy.
- Состояния `NSPasteboard.AccessBehavior`: `.default`, `.ask`, `.alwaysAllow`, `.alwaysDeny`. **Только `.alwaysAllow` разрешает фоновый автоматический программный capture** в MVP.
- До Allow фоновое чтение `pasteboardItems`, `types` и `string` недопустимо. `changeCount` можно отслеживать для определения ревизии без чтения содержимого, но сам вопрос, вызывает ли выбранный native API/bridge privacy prompt, проверить в clean device spike.
- Явный пользовательский `Request Clipboard Access Once` в Settings: проверить status → при `.default`/`.ask` разрешить одно user-initiated обращение, которое **может** вызвать системный prompt; после него снова прочитать status. При `.alwaysDeny` открывать инструкции вместо повторных read.
- Приложение не должно эмулировать «выдано Always Allow» из единичного нажатия user-initiated Paste.
- Изменения permission извне обнаруживаются, статус и доступность функции обновляются без restart; переход в Deny останавливает попытки чтения немедленно.
- Проверка permission НЕ должна иметь побочных эффектов и НЕ должна превращаться в запрос доступа.

### 3. Accessibility (отдельное разрешение)
- `AXIsProcessTrusted()` — status; `AXIsProcessTrustedWithOptions(prompt=true)` — только по осознанному действию пользователя.
- Точное разрешение нужно для автоматической вставки в ранее выбранное поле; **не** требуется для показа истории или Copy Only.
- Отсутствие AX trusted => безопасный Copy Only. Permission может быть выдан/отозван, UI своевременно обновляет state.
- Перед сохранением target исключить `kAXSecureTextFieldSubrole` и любой target без достаточно надёжной идентичности. В отсутствие AX data не выполнять слепой Cmd+V в foreground.

### 4. Session, focus и synthetic paste
- `NSWorkspace.shared.frontmostApplication`, AX-focused window/element, status-item click и global hotkey: snapshot нужно делать **до** активации панели Avalonia.
- Снятие исходного фокуса не должно запаздывать из-за переключения потоков после открытия панели.
- Учитывать приложение на другом Space/full-screen, несколько дисплеев, внешнее переключение app/field, завершение приложения; при несоответствии Copy Only.
- `CGEvent` Command+V только после повторной проверки, одна пара событий; используемый keyCode определяется текущей раскладкой, включая Dvorak/Russian. Не симулировать посимвольный текст.
- Нельзя объяснять пользователю, что «вставлено», если было только posting CGEvent.

### 5. Mac-native menu, hotkey и login
- Нативный menu bar статус-элемент (`NSStatusItem` либо проверенный Avalonia tray backend с эквивалентным поведением). ЛКМ открывает History, ПКМ открывает меню.
- macOS `RegisterEventHotKey`, hotkey callback marshalled в безопасный UI context. Не использовать global event taps / Input Monitoring для наблюдения всех клавиш.
- `SMAppService.mainApp.status` и register/unregister, approval state; установка/перемещение `.app` может влиять на registration — тестировать.

## Product-Significant Architecture And Constraints

Поддерживаемые платформы и общие ограничения определяет IDD-0001. Наблюдаемые гарантии этого документа обязательны независимо от внутренней реализации.

## Non-goals

Нет App Store sandbox distribution и автоматического наследования старых privacy grants.

## Acceptance Criteria

1. `Finder` запускает `.app`, status item виден, Dock icon отсутствует, History получает keyboard focus.
2. Чистая установка: `.default` не вызывает автоматических запросов. После явной `Request Clipboard Access Once` системный запрос появляется по правилам ОС и UI не утверждает false Allow.
3. Состояния `.ask`, `.alwaysDeny` не запускают prompt loop и запрещают фоновые reads.
4. Изменение на `.alwaysAllow` в System Settings включает capture; отзыв выключает его; нет рестарта.
5. Захват одного обычного копирования без AX-доступа, Copy Only без AX; после granting AX — guarded Paste.
6. Secure text field, утраченный focus, другое активное приложение и remote/unsupported target — только Copy Only.
7. US/Russian/Dvorak paste shortcut реальной раскладкой (не только unit test resolver).
8. Установленный signed/ad-hoc bundle имеет понятный статус Gatekeeper, отсутствие требуемой нотификации не обходится отключением системы защиты.
9. Изменения версии при стабильной signing identity не приводят к неожиданной потере privacy authorization; если dev vs release identity разная — проблема ясно задокументирована, права надо перепредоставить.

## Verification

На реальном Mac проверить default/ask/allow/deny, AX grant/revoke, Finder, Dock, focus, bundle identity/signing и обновление. Проверить US/Russian/Dvorak, Spaces/displays, secure/unsupported targets. Dev-host evidence не заменяет installed-app evidence.
