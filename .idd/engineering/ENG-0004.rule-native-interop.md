# ENG-0004.rule-native-interop

## Rule

Изолировать interop с явными ownership, lifetime и thread contracts.

## Applicability

Always

## Applies when

Every implementation change

## Rationale

Явное ограничение исходного ТЗ сохраняет архитектурные границы, контролируемость реализации и проверяемость системной интеграции.

## Guidance

- macOS: Swift/Objective-C native bridge с C ABI, либо проверенная и документированная альтернатива; Windows: P/Invoke/User32/COM UIA. Не вызывать произвольные native API из ViewModel.
- В интерфейсах C ABI строго определить encoding UTF-8, размер буферов, free functions, ownership, lifetime snapshot, вызов на главном потоке, обработку ошибок, cancellation и callbacks.
- Critical race checks (clipboard count + foreground identity) должны происходить максимально близко к действительной OS-operation и не полагаться на cached UI state.
- Все native handles освобождать, не хранить `AXUIElement`/`HWND` бессрочно после закрытия target; test disposal/shutdown.
- Отдельно проверять Apple universal/macOS bundle signing и Windows COM STA/MTA requirements.
- NSPasteboard, NSWorkspace, AXUIElement, CGEvent, Carbon/TIS, SMAppService изолированы тонким типобезопасным adapter. Swift/ObjC C ABI рекомендован; альтернатива требует успешного IDD-0012.
- Не передавать Swift objects как opaque CLR objects без lifetime policy. Разделять revision и checked snapshot; changeCount не глобально монотонен между системными перезапусками. Carbon modifiers не равны normalized shortcut enum.
- Swift shim и зависимости включать/подписывать в bundle для поставляемых архитектур; реальная загрузка из установленного bundle обязательна.
- UI-функции выполняются на dispatcher; callbacks, storage и native interop не создают data races.

## Verification

Проверить соответствие правилам этого документа обзором зависимостей/реализации и соответствующим automated или platform evidence. Реальные разрешения и поведение установленного пакета подтверждаются только на целевой ОС.
