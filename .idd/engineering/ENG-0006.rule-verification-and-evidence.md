# ENG-0006.rule-verification-and-evidence

## Rule

Поддерживать automated/manual traceability и честное evidence обеих ОС.

## Applicability

Always

## Applies when

Every implementation change

## Rationale

Явное ограничение исходного ТЗ сохраняет архитектурные границы, контролируемость реализации и проверяемость системной интеграции.

## Guidance

- Unit-tests на всё Core + Services; integration tests с настоящим SQLite; native adapter tests per OS; ручная матрица real-device системных сценариев.
- Не подменять macOS permission tests mocks — моки только для сервисных unit-tests.
- Каждый IDD acceptance criterion должен иметь ссылку на конкретную automated/manual проверку; хранить матрицу трассируемости и отчёт об evidence.
- Build/test на Windows и macOS в CI; Release отдельно проверять установленный артефакт без SDK, критические hotkeys, capture permissions, Paste/Copy Only.
- При недостатке реального оборудования указывать `not verified`, а не автоматом `passed`.
- Устойчивые архитектурные решения фиксировать ADR/Engineering; изменения поведения — в Intent до/вместе с кодом. Поддерживать evidence и compatibility gaps при изменениях реализации.

## Verification

Проверить соответствие правилам этого документа обзором зависимостей/реализации и соответствующим automated или platform evidence. Реальные разрешения и поведение установленного пакета подтверждаются только на целевой ОС.
