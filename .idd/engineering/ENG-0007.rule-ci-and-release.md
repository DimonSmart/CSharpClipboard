# ENG-0007.rule-ci-and-release

## Rule

CI проверяет обе ОС; релизы и bridge имеют явное версионирование.

## Applicability

Always

## Applies when

Every implementation change

## Rationale

Явное ограничение исходного ТЗ сохраняет архитектурные границы, контролируемость реализации и проверяемость системной интеграции.

## Guidance

- GitHub Actions: windows-latest и актуальный поддерживаемый macOS runner, `восстановление зависимостей, сборка и тесты`, publish для целевых RID, packaging smoke.
- Теги вида `vMAJOR.MINOR.PATCH`, релизные assets с чёткими именами OS/arch, checksums и подписанными metadata при наличии безопасного in-app updater.
- Приложение из CI проверяется на отсутствие SDK requirement, корректную native library loading, отсутствие двух экземпляров, чистоту пакетирования.
- При объединении Swift bridge .NET-код и native binary версионировать синхронно: explicit bridge API version negotiation/fail-fast with human-readable error.

## Verification

Проверить соответствие правилам этого документа обзором зависимостей/реализации и соответствующим automated или platform evidence. Реальные разрешения и поведение установленного пакета подтверждаются только на целевой ОС.
