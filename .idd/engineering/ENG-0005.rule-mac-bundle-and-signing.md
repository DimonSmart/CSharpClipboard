# ENG-0005.rule-mac-bundle-and-signing

## Rule

Для macOS использовать `dev.dimonsmart.CSharpClipboard` как постоянный новый `CFBundleIdentifier` CSharpClipboard. Сохранять этот bundle ID во всех dev- и release-сборках и обновлениях.

## Applicability

Conditional

## Applies when

macOS build/release

## Rationale

Явное ограничение исходного ТЗ сохраняет архитектурные границы, контролируемость реализации и проверяемость системной интеграции.

## Guidance

- Создавать корректный `CSharpClipboard.app` с `Contents/MacOS/`, `Contents/Resources/`, `Contents/Info.plist`; поддерживать необходимые native dylib/framework dependencies, runtime libraries, архитектуры и load paths. Проверить placement managed DLL/resource files согласно актуальным рекомендациям Uno/macOS и подпись каждого Mach-O (включая вложенные native компоненты); нельзя считать, что любой файл можно бездумно положить в `Contents/MacOS`.
- Использовать `dev.dimonsmart.CSharpClipboard` в конфигурации `.app` до первых реальных permission tests; `LSUIElement=true`, minimum macOS 26.
- Нельзя считать `dotnet run` корректным тестом user-level TCC/AX access. Предоставить `scripts/run-macos-dev-app.sh`, собирающий и запускающий стабильный dev `.app` с consistent identity/signature.
- Подписывать nested Mach-O и главный bundle; проверять integrity, designated requirement, исполнимость, load paths и release notarization/Gatekeeper.
- Release target — Developer ID sign + notarize + staple (при наличии сертификатов). Если сертификатов нет, dev ZIP помечен как unsigned/ad-hoc и сопровождается инструкцией разрешить запуск через штатный System Settings, **без** команд отключения Gatekeeper.
- Bundle ID участвует в TCC identity, а изменение bundle ID или signing designated requirement может прервать непрерывность privacy permissions при обновлении. Сохранять выбранный bundle ID и согласованную signing identity в рамках соответствующего release channel. Dev/release могут иметь разные privacy grants — это честно документируется.
- Автозапуск через `SMAppService` работать должен из установленного `.app`, а не из случайно перемещённого temp executable.

## Verification

Проверить соответствие правилам этого документа обзором зависимостей/реализации и соответствующим automated или platform evidence. Реальные разрешения и поведение установленного пакета подтверждаются только на целевой ОС.
